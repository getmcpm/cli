## Verified defects addressed

| Boundary | Before | Corrected behavior |
| --- | --- | --- |
| Client configuration | Invalid JSON roots/server-map containers could look empty or be rewritten | All adapters reject invalid containers before mutation; valid JSONC and unrelated state survive |
| MCP removal | Adapter read/write failure could be reported as successful removal | Preflight target presence across configs; propagate read/write failures and preserve tracking on adapter failure |
| Local store removal | Remove/update treated every store exception as an absent record | Only a typed missing record is tolerated; I/O and parse failures propagate |
| External scanner | Malformed JSON fields could throw or corrupt severity/score values | Validate the external result shape; inherited/unknown severity keys cannot corrupt scoring |
| Integrity gate | Multiple digests for one algorithm used the last token | Compare complete digest sets for the existing strongest shared algorithm, independent of token order |
| Re-locking | Unreadable/malformed prior lock could be treated as absent and overwritten | Only actual absence is absent; uncertain prior state refuses replacement |
| Import/export | Unreadable clients could disappear behind a clean empty/complete claim | Surface omitted clients without printing arbitrary exception content |

Each change has failing-before/passing-after regressions. Removal remains
nontransactional: a later write/store failure can follow earlier successful
config writes. The correction reports that failure; it does not promise rollback.
Scanner execution is user-configured; malformed scanner output is not presented
as a demonstrated hostile-server exploit. SRI comparison retains the existing
strongest-common-algorithm policy; it does not authenticate the running server.
