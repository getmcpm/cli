Make the next decision
with evidence.

From the public registry to an explicitly wrapped server, keep the checks and their gaps in view.

01Discover

Find the server. Read the signals.

Search the official MCP registry for candidate servers and their lifecycle status.

mcpm search filesystem
02Assess

Understand what is behind the score.

Review computed trust components, metadata findings, and checks that did not run before deciding to install. Assessment does not execute the server or audit its source.

mcpm why <server-name>
03Install

Add the reviewed server to your client.

Write the selected server to client configuration. Installation alone does not enroll it in runtime protection.

mcpm install <server-name>
04Enable guard

Choose runtime protection explicitly.

Preview changes for the installed server, then enable the stdio wrapper. Restart that server in your client to load it.

mcpm guard enable --server <server-name> --dry-run
mcpm guard enable --server <server-name>

Trust scores are signals, not guarantees.

A score is not a safety probability. Metadata checks do not execute servers, and matching package records do not prove safe behavior.

Guard covers wrapped stdio traffic.

Enable the wrapper and restart the affected server. HTTP/SSE servers have no runtime inspection from guard. Warnings forward traffic; blocks substitute an error.

The first observation becomes a baseline.

Tool pins use trust on first observation. Initial malicious definitions can become the baseline. Review actual changes before accepting drift.
